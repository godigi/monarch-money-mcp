# Monarch transaction tools

The operator approved extending the current OAuth-protected VPS connector with tags, native rules and receipt attachments, keeping the existing URL and supporting ChatGPT Work and Claude Code. This is the approved chat description made concrete; routine implementation decisions below are the implementer's choices.

Expose tag listing, creation and additive assignment. Adding tags reads the exact requested transaction (without redirecting a pending transaction to its posted counterpart), preserves its current tags, validates requested IDs and verifies the result. Concurrent writes to one transaction are serialized within this server.

Expose transaction details, native rule listing, rule preview and rule creation. Support merchant/original statement contains or exact matching, account/category restrictions and amount comparisons; actions cover category, merchant rename, adding tags, visibility and review status. A preview scans a specified date window, omits pending transactions and shows matching records and proposed actions. A complete bounded preview creates a short-lived opaque ID tied to that rule. Creation consumes that ID, defaults retroactive application off, and reports the native rule ID; it must not automatically retry an uncertain mutation. Preview is an estimate of this rule alone, not a simulation of every other rule or future bank arrivals.

Expose native attachment upload to an existing transaction, not Monarch's separate receipt-scanning/OCR import pipeline. Accept JPEG, PNG, WebP or PDF up to 10 MiB. ChatGPT uses the documented OpenAI file-object schema and fileParams metadata. A local Claude Code helper reads an explicitly selected file and transfers bytes to the same remote OAuth server. Do not interpret a client path as a VPS path. Validate signatures, filenames and byte limits; limit external downloads to HTTPS public addresses with connection-time DNS validation and bounded redirects. Do not forward the Monarch cookie or OAuth tokens to file hosts or Cloudinary. Use Monarch's signed Cloudinary upload parameters then link the resulting asset and verify it appears on the transaction. Keep receipt bytes and signed URLs out of logs and disk.

Preserve GitHub user allowlisting, secret-file authentication and the absence of legacy REST routes. Tests use synthetic data and external transport doubles. Production validation may read financial data but only emits counts; no real transaction, tag or rule is changed without a specific operator-approved test record. Deployment is through the existing Coolify application. Refresh ChatGPT's tools after deployment. Record infrastructure state in VPS_STATUS and CHANGELOG.
